OnePay Payment Provider

OnePay, Musrefy Pay, Yussor Online and Sahara Pay — four Libyan wallets, one module

The customer types their identity card number, the gateway texts them a 6-digit one-time password, they type it in, and the order is paid — all on the checkout page. It is an ordinary Odoo payment provider: it works anywhere payment works, in eCommerce checkout, portal invoices, subscriptions and payment links.

Four providers, not four modules

The branded deployments all speak the same API and differ only in their credentials and in the prefix applied to a short identity card number. Each is installed as its own payment provider record with its own credentials, so you can enable one, some or all of them side by side.

Customers who type their full card number are unaffected; only short numbers are completed.

Pending payments settle themselves

A customer who closes the tab before entering the OTP — or loses signal halfway through — leaves a transaction pending while the money may already have moved. An hourly scheduled action looks each pending transaction up in OnePay's own transaction report and settles the ones the gateway confirms. Transactions younger than ten minutes are left alone so the sweep never races a customer still typing their OTP, and the sweep looks no further back than a day.

Any pending transaction also carries a Check with OnePay button, so support can settle one on the spot without waiting for the next run.

What you get

Mutual TLS in production

Upload the PEM client certificate, private key and CA bundle the gateway issues you and enabled providers authenticate over mutual TLS. The material is written to temporary files with mode 0600 for the length of a single request and removed afterwards, even if the request raises. Providers left in test mode use plain HTTPS, so you can develop without production certificates.

Configuration errors caught at save time

Enabling a provider with credentials missing fails with a message naming the empty fields, and TLS material that is not PEM is refused when you upload it — not discovered by a customer at checkout.

Credentials kept out of reach

The sign-in PIN, the client certificate and the private key are restricted to Settings administrators and never reach the customer's browser. Gateway errors are written to the server log; the checkout page shows only a message the customer can act on.

Endpoints you can override

The gateway hands different API paths to different merchants, so the sign-in, init, complete and report paths are all editable per provider. Sensible defaults are filled in, and most merchants never touch them.

Setting it up

Go to Invoicing › Configuration › Payment Providers and open the provider you were issued credentials for. Fill in the API Base URL, User ID, PIN and Gateway Provider ID, attach your TLS material if you are going live, then enable and publish it. Repeat for each brand you accept.

Before you install

You need a merchant account with OnePay or one of its branded deployments, and the credentials issued with it. This module is the Odoo side of that integration; it does not obtain the account for you.

Payments are taken in Libyan Dinar (LYD) only, the sole currency the gateway accepts. The wallet does not support refunds, saved payment methods, express checkout or manual capture through the API, so those Odoo features stay off for these providers — refunds are handled outside Odoo.

The certificate and private key are stored in the database like any other Odoo binary field, which means they are readable from a database dump or filestore backup. Treat your backups accordingly.
