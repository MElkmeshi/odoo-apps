Partner Phone (Egypt)

One canonical number per contact — no duplicates, found however it is typed

The same customer gets entered twice as +20 100 123 4567 and 01001234567, and nothing stops it — because to Odoo those are two different strings. This module stores every Egyptian mobile in one canonical form and builds duplicate prevention and search on top of it.

What you get

Duplicates are refused

Saving a contact whose number an active contact already holds fails with a message naming who has it — not a database error. The guarantee is a partial unique index in PostgreSQL, so two people saving the same number at the same moment cannot both get through.

Search by number, any format

Type a phone number into any contact field and the contact is found, whether you type it the way it is stored or the way it appears on the customer's own screen. Searching by name keeps working exactly as before.

Nothing else is touched

Landlines, foreign numbers and blank fields are left exactly as entered and are not covered by the uniqueness rule — only real Egyptian mobiles (010, 011, 012, 015) are. Archived contacts release their number for reuse.

One field, no configuration

Adds a single stored field, phone_normalized, computed from the contact's phone. Install it and existing contacts are normalised automatically. There is nothing to set up.

Before you install

If your database already contains two active contacts sharing a number, the unique index cannot be created until you merge or archive one of them. Odoo reports which records conflict.

Saving a contact also rewrites its phone field to the canonical form. If you need the number preserved exactly as typed, this module is not for you.

Works well with

Phone in Contact Name — shows the number next to the contact's name, so two similarly named contacts are told apart at a glance. Independent; install either or both.
